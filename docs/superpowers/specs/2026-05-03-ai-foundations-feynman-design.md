# AI 技术基础费曼学习法教材设计文档

## 1. 项目目标

本项目要产出一份中文长篇 Markdown 教材，帮助读者使用费曼学习法系统复习现代 AI 技术基础。教材主线从神经网络出发，逐步解释深度学习、Transformer、注意力机制、大语言模型、RAG、智能体，以及 Harness Engineering 相关的 Prompt Engineering、Context Engineering、Evaluation Harness 和 AI 应用工程脚手架。

教材不追求论文式堆叠，也不只停留在科普层面。核心目标是让读者能够：

- 用简单语言解释每个概念的动机、机制和边界。
- 理解关键数学直觉，包括矩阵运算、梯度下降、概率建模和注意力计算。
- 看懂现代 LLM 应用系统的基本架构图。
- 区分模型能力、应用编排、检索系统、评测系统和智能体系统之间的责任边界。
- 通过自测题和复述练习发现自己是否真的理解。

## 2. 读者设定

默认读者具备大学数学基础，熟悉线性代数、微积分和概率论的基本概念，但不假设读者已经系统学习过深度学习。编程方面默认读者能读懂基础 Python，对 PyTorch 或 NumPy 有初步印象即可。

写作层级采用“先 A 后 B”的方式：

- 第一层解释使用高中数学和日常类比，让概念先站住。
- 第二层解释补充大学数学视角、公式直觉、伪代码和工程语境。
- 第三层解释指出和论文、真实系统、常见失败模式之间的连接。

## 3. 交付物

采用 A+B 混合做法：

1. 主教材：一份完整、可独立阅读的长篇 Markdown 文档。
2. 视觉辅助笔记：按章节拆分的笔记素材目录，用来弥补 Markdown 纯文字不够直观的问题。

建议文件结构：

```text
AI基础费曼学习法教材.md
notes/
  visual-aids/
    01-neural-networks.md
    02-deep-learning.md
    03-transformer-attention.md
    04-large-language-models.md
    05-rag.md
    06-agents.md
    07-harness-engineering.md
    08-feynman-review-path.md
```

主教材负责完整叙事和逻辑递进。视觉辅助笔记负责图示、流程图、类比图、结构图、表格、生成图片提示词、论文/教材图引用建议和章节速记卡片。

## 4. 章节设计

### 4.1 从函数近似器理解神经网络

本章从“神经网络是在调一大堆旋钮来拟合输入和输出之间的关系”开始，解释神经元、权重、偏置、激活函数、层、前向传播、损失函数、梯度下降和反向传播。

本章需要覆盖：

- 标量、向量、矩阵视角下的神经网络。
- 为什么线性层叠加后仍然是线性的，为什么需要非线性激活函数。
- 损失函数如何把“模型错得多离谱”变成一个可优化的数字。
- 梯度下降如何沿着损失函数的坡度调整参数。
- 反向传播不是魔法，而是链式法则在计算图上的高效复用。

视觉辅助重点：

- 单个神经元图。
- 多层网络的信息流图。
- 损失曲面和梯度下降示意。
- 反向传播的计算图。

### 4.2 深度学习为什么“深”

本章解释深度学习的核心价值是表示学习：模型通过多层结构逐级提取更抽象的特征。它需要承接传统机器学习和深度学习的差异，同时讲清 CNN、RNN 在历史中的位置，为 Transformer 的出现做铺垫。

本章需要覆盖：

- 表示学习与人工特征工程的差别。
- 深层网络如何形成层级特征。
- 过拟合、欠拟合、正则化、数据增强和归一化。
- 优化器、学习率、batch、epoch 等训练概念。
- 数据、算力、模型规模共同推动深度学习发展的原因。

视觉辅助重点：

- 人工特征工程与表示学习对照图。
- 欠拟合、合适拟合、过拟合曲线图。
- 训练循环流程图。
- CNN、RNN、Transformer 的历史位置对照表。

### 4.3 Transformer 与注意力机制

本章是全教材的核心技术桥梁。解释注意力机制时先从“当前词要看哪些上下文”出发，再进入 Query、Key、Value 的计算直觉。随后解释自注意力、多头注意力、位置编码、残差连接、LayerNorm、前馈网络、编码器、解码器和 causal mask。

本章需要覆盖：

- 为什么 RNN 难以并行处理长序列。
- 注意力机制如何让每个 token 直接访问其他 token。
- Q/K/V 的向量匹配直觉和矩阵计算形式。
- softmax 如何把相似度变成权重分布。
- 多头注意力为什么像从多个角度阅读同一句话。
- 位置编码为什么必要。
- Transformer block 的组成和信息流。

视觉辅助重点：

- Q/K/V 注意力计算流程图。
- 单头和多头注意力对照图。
- Transformer block 结构图。
- causal mask 示例矩阵。

### 4.4 大语言模型

本章从 Transformer 过渡到 LLM，解释 tokenization、next-token prediction、预训练、指令微调、RLHF/RLAIF、上下文窗口、幻觉、Scaling Law、推理成本和部署方式。

本章需要覆盖：

- 语言模型预测的是 token 分布，而不是直接“理解世界”。
- 为什么 next-token prediction 可以学到语法、知识和推理模式。
- base model、instruction model、chat model 的差异。
- prompt、system message、temperature、top-p、context window 的作用。
- 幻觉的根源和缓解策略。
- 参数量、数据量、算力、延迟和成本之间的关系。

视觉辅助重点：

- tokenization 示例。
- 预训练、指令微调、偏好对齐流程图。
- LLM 推理时的 token-by-token 生成图。
- 模型能力、成本、延迟权衡表。

### 4.5 RAG

本章解释 RAG 的动机：模型参数不是数据库，上下文窗口也不是可靠知识库。RAG 通过检索外部资料，把相关证据放入上下文，再让 LLM 基于证据生成回答。

本章需要覆盖：

- RAG 解决的核心问题：知识更新、私有数据、可追溯引用和降低幻觉。
- 文档加载、清洗、切分、embedding、向量索引、召回、重排、上下文组装。
- sparse retrieval、dense retrieval、hybrid search 的差异。
- chunk size、overlap、metadata、reranking 对效果的影响。
- RAG 常见失败模式：切分错误、召回遗漏、上下文污染、引用不实、生成偏离证据。
- RAG 评测：检索质量、答案忠实度、引用准确性和端到端任务成功率。

视觉辅助重点：

- RAG pipeline 图。
- embedding 空间的类比图。
- chunking 策略对照图。
- 查询、召回、重排、生成的阶段性失败模式表。

### 4.6 智能体

本章解释智能体不是“更聪明的模型”，而是把 LLM 放进一个能观察、计划、调用工具、记录状态并持续执行的循环中。需要区分 workflow、agent 和 multi-agent。

本章需要覆盖：

- LLM、工具、记忆、规划器、执行器、环境反馈的关系。
- ReAct 模式：reasoning 与 acting 交替。
- function calling 与 tool calling 的工程意义。
- planner-executor、reflection、self-correction 的作用与风险。
- 工作流和智能体的区别：确定流程优先还是动态决策优先。
- multi-agent 的收益、复杂度和常见误用。
- 安全边界：权限、确认、沙盒、日志、回滚和人类审批。

视觉辅助重点：

- Agent loop 图。
- workflow 与 agent 对照图。
- ReAct 思考-行动-观察循环图。
- 单智能体与多智能体系统责任边界图。

### 4.7 Harness Engineering 总章

本章统一解释 Prompt Engineering、Context Engineering、Evaluation Harness 和 AI 应用工程脚手架。重点是从“会调用模型”提升到“能构建可靠 AI 系统”。

本章需要覆盖：

- Prompt Engineering：任务说明、角色、约束、示例、输出格式、错误处理。
- Context Engineering：上下文选择、压缩、记忆、检索、工具结果、会话状态。
- Evaluation Harness：测试集、benchmark、自动化评测、人工评审、回归测试、对比实验。
- AI 应用工程脚手架：模型网关、工具注册、权限控制、日志、监控、缓存、成本控制、fallback。
- 观测与调试：trace、span、prompt/version、retrieval log、tool call log。
- 可靠性设计：guardrails、schema validation、retry、timeout、circuit breaker、人类确认。

视觉辅助重点：

- 从 prompt 到 production harness 的成熟度阶梯。
- LLM 应用系统架构图。
- eval harness 流程图。
- prompt、context、retrieval、tool、eval 的责任分工表。

### 4.8 费曼复习路径

本章把前面内容转成学习方法。每章都要配套“解释给小学生听”“用大学数学复述”“用工程师视角复述”“自测题”“常见误区”“最小代码直觉”和“下一步阅读”。

本章需要覆盖：

- 如何用费曼学习法复习 AI 技术。
- 如何判断自己只是记住名词，还是理解机制。
- 如何用图、表、类比、伪代码交替验证理解。
- 如何建立从概念到工程系统的知识地图。

视觉辅助重点：

- 学习路线图。
- 概念依赖关系图。
- 自测清单。
- “能讲清楚”的判断标准表。

## 5. 视觉辅助策略

视觉素材以“笔记式补充”为主，不让主教材依赖复杂渲染环境。优先使用以下形式：

- Mermaid 图：流程、架构、依赖关系、循环。
- ASCII 图：小型局部机制，例如矩阵流向、token 生成过程。
- 表格：对比概念、常见误区、工程权衡。
- 图片提示词：为 ChatGPT image 2.0 或其他图像模型准备可复用提示词。
- 外部图引用建议：标注适合引用的论文图、教材图或官方文档图，避免直接复制受版权保护内容。
- 自绘图说明：如果后续需要生成图片，说明图中对象、布局、颜色和标注。

若使用论文或教材图片，应优先选择开放许可、官方论文中的图，或只给出引用链接和“建议查看哪张图”的说明，而不是把受版权保护图片直接嵌入仓库。

## 6. 写作风格

教材使用中文，风格要求是“深入浅出但不稀释技术含量”。

每个核心概念尽量按以下顺序展开：

1. 一句话定义。
2. 为什么需要它。
3. 用生活类比解释。
4. 用数学或伪代码解释。
5. 放到真实 AI 系统中看它的角色。
6. 常见误解。
7. 自测问题。

避免只罗列术语。每章都要不断回到费曼学习法：如果读者不能用自己的话解释它，就说明还没有真正掌握。

## 7. 资料与事实准确性策略

涉及现代 AI 技术、模型训练实践、RAG 和智能体工程时，需要尽量使用一手资料或权威资料校验：

- 经典论文：例如 Attention Is All You Need、BERT、GPT 系列相关公开论文、InstructGPT、RAG、ReAct。
- 官方文档：模型 API、function calling、tool calling、embedding、eval、agent SDK 等以官方文档为准。
- 教材与课程：深度学习教材、Stanford CS224N、CS231N 等公开课程资料可作为解释参考。

最终教材中需要区分稳定概念和快速变化的工程实践。对快速变化内容要避免写成永久结论，并在必要处标注“截至写作时”的语境。

## 8. 验收标准

完成后的主教材应满足：

- 覆盖神经网络、深度学习、Transformer、注意力机制、大语言模型、RAG、智能体和 Harness Engineering。
- 每章包含费曼式解释、数学直觉、工程直觉、常见误区和自测题。
- Transformer、RAG、Agent、Harness Engineering 至少各有一张结构图或流程图。
- 视觉辅助笔记目录存在，并按章节提供图示、表格或生成图片提示词。
- Markdown 层级清晰，适合后续继续扩写。
- 没有明显的概念跳跃：读者能从神经网络一路自然过渡到 LLM 应用系统。
- 对快速变化的内容保持谨慎，不把特定厂商或短期工具形态误写成长期规律。

## 9. 非目标

本项目当前不直接产出完整网页、PPT、视频课程或可运行代码项目。教材可以包含伪代码和小段 Python 直觉代码，但不以训练完整模型或搭建完整 RAG 系统为主要交付。

本项目不直接复制论文、教材或商业课程中的受版权保护图片。需要视觉辅助时，以自绘图、Mermaid 图、图像生成提示词、官方链接和简短引用建议为主。

## 10. 后续实施顺序

后续实施建议按以下顺序推进：

1. 创建主教材文件和视觉笔记目录。
2. 先写完整目录、阅读说明和费曼学习法使用方式。
3. 按章节逐步写正文，每章先完成概念主线，再补数学直觉和工程视角。
4. 为每章补充视觉辅助笔记。
5. 统一检查术语、章节递进、图表编号和自测题。
6. 对涉及最新工程实践的内容进行资料校验。
7. 做最终 Markdown 可读性检查。
